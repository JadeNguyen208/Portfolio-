Zero friction at 1AM

“Every design decision should minimise the cost of being awake.”

Rain + Ocean means two scenes at once. Each gets a dominance weight, alpha-composited by volume — turn Rain to 80% and its visual takes over.

01 — The Brief

Premium, before a single word

Every luxury fruit brand runs the same playbook. The harder brief: make the price feel justified before the visitor reads anything — a job that falls entirely on design and frontend craft.

02 — Motion as Hierarchy

Timing is the composition

Each fruit floats at its own speed:

  • Orange · 3.2s — focal point, the anchor speed
  • Lemon · 2.8s — fastest, adds energy
  • Watermelon · 3.6s — slowest, grounds the system
03 — Designed Provenance

Origin as interface

Real farm photography builds trust; hand-drawn Canvas fruit gives the brand its crafted character, every highlight controlled in code.

The interactive SVG map makes provenance visible: Khánh Hòa glows as the single-origin region, with province tooltips and no map API.

One glowing province says “single origin” faster than a paragraph.

Khánh Hòa — single-origin region · hover to explore

04 — Three ML Systems on a Firebase Backend

Where this becomes ML engineering

Smart features ship as quiet micro-interactions, never an “AI feature” banner. Three are real ML systems, not API wrappers, and each degrades to a documented fallback so the storefront stays usable. A fourth — the delivery-zone check — is rule-based on purpose.

They sit on a real backend — Firebase Auth, Firestore and Cloud Functions, so a solo build still gets real accounts and real data:

  • Login — Google or email, with a customer profile
  • Order history — each customer sees their own past orders; Firestore security rules keep everyone else's private
  • Admin — an admin role updates order status and rebuilds the recommender from real orders
  • AI proxy — Gemini calls go through a Cloud Function, so the API key never reaches the browser
SystemTechniqueWhere it runs
Product RecommenderItem-based collaborative filtering — co-occurrence over real orders, recent orders weighted higher (90-day decay)Built from Firestore orders · served as anonymous aggregate stats
Farm Advisor ChatbotRAG — keyword retrieval over knowledge base + catalogue, injected as contextClient retrieval · Gemini via a Cloud Function
Fruit RecogniserTransfer learning — MobileNet embeddings, cosine-similarity KNN over the farm's own photosTensorFlow.js, 100% client-side

It started as a colour heuristic — plausible numbers, no model. Rebuilding it on embeddings was the difference between a UI trick and an ML system honest about how it fails.

3ML systems — recommender, RAG, vision
4Firebase services — Auth, Firestore, Functions, Hosting
21Reference photos across 14 SKUs
Honest about the limits

MobileNet is pretrained on ImageNet, not fine-tuned on Vietnamese fruit — it works by nearest-neighbour against the farm's own photos. Next step: more labelled photos and a fine-tuned classification head. I'm building the theory behind that through HarvardX: Data Science — Machine Learning.

04 — Grid & HUD

Isometric math that snaps, a UI that retreats

Real app · Level 13 · 40+ plots

The grid

True isometric, 2:1 tiles. gridToWorld places a tile; worldToGrid snaps any click to the nearest cell. Green = free, red = blocked — placement validates live.

x = (gx − gy) · TILE_W/2  ·  y = (gx + gy) · TILE_H/2

The HUD

The world is loud on purpose, so the interface is restraint: every chip on its own scrim, one jade accent for progress, and an icon-only rail that collapses. The level bar shows 2500/5440 and “2,940 points to level 14” — where you are, and what to do next.
